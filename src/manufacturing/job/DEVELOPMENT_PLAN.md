## 1. 目标与完成定义

加工 Job 是 CAM 长期状态的唯一可序列化真值。项目文件只保存重建所需的稳定输入；打开项目后重新识别/重绑定模型、重建派生刀路，并按输入指纹决定哪些运行期结果与 IPW 前缀仍可复用。

```text
零件/毛坯/Setup/刀库/工艺输入
  -> MachiningJobDefinition
  -> 结构验证与规范化 JSON
  -> QSaveFile 原子保存
  -> 加载到候选定义
  -> 源文件校验、Setup/拓扑重绑定
  -> 各领域确定性再生成
  -> MachiningJobRuntime 与统一 IPW 重建
  -> 全部成功后原子安装到活动工作区
```

Job 不保存 OCCT 刀路、TopoDS 形状、显示网格、后台任务、Widget 状态或 IPW 检查点。运行期对象可丢弃且必须能由定义重建。

OpenCAMLib 精加工已作为独立 `SurfaceFinishing` 正式工序接入。其目标引用完整实体 ID 集合，工序保存刀具快照、装夹、算法 ID 和每道工序的采样参数；重开时重新构建完整目标并生成派生刀路。旧版曲面加工定义仍不兼容，不能直接改名后复用。

桌面名称现为“雕刻”，统一参数页支持专用刀库或直接填写单刀；默认六面，可选仅 +Z。内部 `SurfaceFinishing` 类型与 v11 存储键保持兼容。直接单刀写入合法刀具快照与空 libraryId，不恢复历史 manual 控制器标志。`replaceFamily` 仅在全部面生成及验证成功后发布；保留既有面的稳定 ID、启用状态与顺序，删除不再请求的雕刻面并清理不再引用的刀具控制器。前序孔槽轮廓定义不变，IPW 显式选择子集不会因删除面而被扩成全选。

精加工消费入口 `currentFinishingResult()` 检查领域指纹、全部启用工序的唯一完整覆盖，以及刀具、参数和工作坐标绑定。捕获与重建成功后立即重配置当前 IPW 计划，保留不变前缀并使变化后缀失效。全部禁用时允许保存及重开，不产生可执行精加工批次。跨领域协调仍按类型实现，显式父依赖尚待收敛。

正式工序集成不改变算法能力边界：当前精加工为固定刀轴平行扫描的采样刀刃接触路径，IPW 减料与参考 NC 导出不等于完成刀杆、刀柄、夹具及连续运动的碰撞认证。

## 3. 不可破坏的契约

1. `MachiningJobDefinition` 是可持久化真值，`MachiningJobRuntime` 是可清除派生缓存。
2. JSON 保存稳定值和引用，不保存 moves、primitives、TopoDS、Dexel、AIS 或 UI 控件状态。
3. 每个正式工序 ID 唯一，启用工序 `sequence` 非负且在全 Job 中唯一。
4. 工序引用的 Setup 和 ToolController 必须存在；无引用资源可在事务成功后清理。
5. Job 刀具是创建/确认时的不可变快照；刀库变化不能静默修改旧 Job。
6. Setup 确认绑定输入指纹，零件、原点、轴向或 WCS 变化后必须失效。
7. 稳定拓扑引用重开后必须唯一重绑定并通过几何指纹校验，不按旧数组下标猜测。
8. 反序列化、捕获、重绑定和保存同步使用候选副本，验证通过后再替换活动定义。
9. 定义变化只复用完全相同的连续 IPW 前缀；不能保留错误下游运行期结果。
10. schema 迁移向后读取、始终按当前版本写出，不原地修改用户文件后再报告失败。

## 5. schema v11 与旧项目兼容

- v11 移除人工孔计划、人工局部批次、单工序手动覆盖及手工刀具控制器。
- 历史项目中存在非空人工定义、局部批次、覆盖值或手工刀具时明确拒绝加载；不将其静默转换成自动工艺。缺少这些字段或仅含空旧字段的自动项目可迁移，仍须通过正常结构验证。
- 旧自动孔工序默认写出的 `operation_overrides: {"retract_preference": 0}` 视为未覆盖，可以迁移；非默认值及其他覆盖字段不作此处理。
- 刀具由活动刀库分配并冻结快照；自动生成所需的深度、余量、步距等参数继续保存。缺刀时报告失败。
- v9 曾移除旧版曲面加工定义；v10 新增 `surface_finishing_operations`，与旧 `surface_operations` 明确区分。
- 新字段保存完整实体 ID 集合及几何指纹、Setup/ToolController 引用、算法 ID、采样与刀具参数、启用状态、全局序号和输入指纹。移动、原语和网格仅存在于运行期。
- v1–v9 缺少旧 `surface_operations` 或该字段为空数组时，保留孔、槽腔和外轮廓定义并迁移到当前版本，不凭空创建精加工工序。
- 旧 `surface_operations` 非空或类型错误时，在修改调用方定义前明确拒绝加载，避免再保存时静默丢失工序。此约束也适用于标记为当前版本的文件。
- v10 起要求 `surface_finishing_operations` 为数组；每道工序的参数、枚举、预算、引用和全局唯一性均须通过验证。旧版本文件不能携带非空的新精加工数组来绕过版本检查。
- 拒绝后由兼容旧版曲面模块的软件处理原项目；加载器不改写原文件，也不自动迁移两种不同算法的参数语义。
- 执行指纹和 IPW 引擎身份随模块范围变化更新，旧缓存不可直接沿用。

## 6. 后续重点

- 统一工序依赖、资源引用和失效范围投影，减少按领域重复协调。
- 明确领域全局参数与工序级快照的职责，迁移时保持旧加工语义。
- 区分定义、领域执行和单工序输入指纹，避免无关变化引发全量重建。
- 项目包记录外部零件、毛坯、碰撞模型、刀库及 post 的路径与内容指纹。
- 工序树、覆盖审计、拾取和 IPW 时间线继续使用正式工序 ID；运行期展开 ID 仅用于播放定位。
- 清理 Setup 与 ToolController 必须依据四类工序的完整引用集合。

## 7. 构建与验收

```powershell
cmake --build build --config RelWithDebInfo --parallel 6 -- /verbosity:minimal

ctest --test-dir build -C RelWithDebInfo --output-on-failure --parallel 4 `
  -R "^(machining_job|surface_finishing_job|surface_finishing_ipw|surface_finishing_project|machining_project_controller|machining_workspace|app_workflow_controllers|multi_dexel_ipw|toolpath_program|module_boundaries)$"
```

schema 或公开领域类型变更必须运行所用构建配置的全量测试、文档链接检查和 `git diff --check`。每个 schema 版本都要保留至少一个最小向后兼容夹具。v10 回归包含 v8/v9 无旧曲面工序迁移，以及旧曲面数组非空或类型错误时的事务式拒绝。
