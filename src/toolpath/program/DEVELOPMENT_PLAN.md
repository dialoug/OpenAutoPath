本文维护 `oap_toolpath_program` 的交付路线。模块只消费中立 `ToolpathProgram`，不依赖孔、槽腔、外轮廓生成器内部类型。加工 Job 的持久化身份见 [../../manufacturing/job/DEVELOPMENT_PLAN.md](../../manufacturing/job/DEVELOPMENT_PLAN.md)。

## 1. 目标与完成定义

程序模块是所有 CAM 工序进入 NC 输出的唯一边界。它必须证明输出来自当前有效 Job、已确认 Setup、已验证工具和完整 IPW 链，并按照控制器能力把中立移动/原语转换为一个或多个可审计程序文件。

```text
已验证 Job 工序与 ToolpathProgram
  -> 全局 sequence 组装
  -> 按 Setup / WCS / 刀具 / 阶段分包
  -> 中立程序验证
  -> 后处理器能力检查与 NC 生成
  -> NC 文本审计
  -> 临时文件写入、原子替换、清单/指纹发布
```

当前 `ReferenceNcGCodePostProcessor` 是参考格式，不是任何生产控制器的认证后处理器。程序模块不负责几何接触求解、材料仿真或 UI 文件对话框。

## 2. 当前实现基线

| 能力 | 当前实现 | 状态 |
| --- | --- | --- |
| 中立模型 | Pocket、Profile、Hole 三类操作，移动和语义原语共享结构 | 已完成 |
| 程序验证 | 工序 ID、Setup 一致性、刀具上下文、移动/原语和参数聚合验证 | 已完成 |
| 参考后处理 | WCS、线性移动、圆弧/螺旋 fallback、固定循环、冷却和摘要 | 已完成 |
| 文本审计 | 单位、绝对坐标、安全模态、固定循环 R 平面、括号和结束码 | 已完成 |
| 原子导出 | 内存后处理成功后才使用文件写入；失败不截断已有文件 | 已完成 |
| 桌面接入 | 活动孔/槽腔/Profile 预览可校验并导出参考 NC | 已完成 |
| 正式项目程序组装 | `MachiningProgramAssembler` 校验 Job 结构、Setup/刀具快照和三领域执行指纹，按全局 `sequence` 组装并保留正式/运行期 ID 映射 | 已完成 |
| 项目程序分包门禁 | `MachiningProgramPartitioner` 证明完整 Ready IPW/检查点链与当前正式工序一致，并按连续 Setup/WCS、刀具控制器和 Hole 阶段保守分包 | 已完成 |

目前的核心缺口是项目级输出发布：正式 Job 已能形成按全局顺序排列、可追溯且经过最终 IPW 门禁的保守分包；导出物还没有与 Job 定义指纹、IPW 最终 `stateKey`、后处理器版本和输入文件建立不可变清单，也没有整包原子替换事务；缺少控制器能力模型及真正生产后处理器的准入机制。

## 3. 不可破坏的契约

1. 几何生成器不得直接拼接 G-code；所有输出必须经过中立程序边界。
2. 程序验证不依赖生成器私有类型，不按工序来源绕过公共移动/原语验证。
3. 语义原语必须有等价执行流；后处理器不支持时只能安全展开或明确失败。
4. 一个输出包内的 Setup、WCS、刀具和阶段边界必须满足对应后处理器能力。
5. 未确认 Setup、过期 Job 结果、非 Ready IPW、验证失败或仅预览程序不得生产导出。
6. `GCodeReview` 只证明参考文本结构，不声称机床运动学、碰撞或控制器语法认证。
7. 后处理失败、文本审计失败或文件写入失败不得覆盖已有有效输出。
8. UTF-8 路径通过仓库统一路径适配进入文件系统。
9. 输出必须可追溯到 Job/操作/刀具/Setup/IPW/后处理版本和程序内容指纹。
10. 控制器专有能力必须显式声明，不允许因“常见 G-code”假设静默输出。

## 5. G3 实施清单

### 5.1 项目级程序组装器

- [x] 输入是已生成且执行指纹匹配的正式 Job 结果，不读取活动预览作为真值；
- [x] 按所有启用工序的全局 `sequence` 组装，拒绝缺失、重复或没有运行期结果的操作；
- [x] 以 Setup/WCS 为硬边界，当前参考能力按刀具控制器和 Hole 阶段保守拆分，只合并连续同键工序；
- [x] 保留操作 ID、来源工序类型、Setup、刀具、阶段和顺序映射，供回放与导出报告复用；
- [x] 当前全局组装不改变单个工序内部移动/原语顺序；后续分包必须继续保持该不变量；

### 5.2 新鲜度与追溯门禁

当前分包门禁与后续导出请求合计至少携带并校验：

- [x] Job definition fingerprint 与各领域 execution fingerprint；
- [x] 每个正式操作 input fingerprint，并与 IPW 节点计划逐项一致；生成验证证据继续由各领域正式 runtime 发布门禁负责；
- [x] 完整 Ready IPW 节点/不可变检查点链及最终 `stateKey`/content fingerprint；
- [x] Setup 输入/确认指纹、WCS 与刀具控制器快照；
- [ ] post ID、版本、能力配置和导出选项；
- [ ] 中立程序内容指纹及最终 NC SHA-256。

任一值缺失或不一致时拒绝生产导出，并返回机器可读错误码。

### 5.3 原子多文件输出

- 先在内存生成并审计全部程序，再写同目录临时文件；
- 全部临时文件、清单和校验和成功后才提交替换；
- 任一文件失败时清理临时产物，保留旧发布包；
- 清单记录建议文件名、程序号、Setup/WCS、刀具、操作 ID、预计时间和指纹；
- 文件名冲突、非法程序号和大小写碰撞在写盘前检查。

### 5.4 G3 必须新增的测试

- [x] Hole/Pocket/Profile 混合全局 sequence 的组装映射；
- [x] 多 Setup、多刀、孔阶段切换及同刀连续工序合并；
- [x] 缺运行期结果、过期执行指纹、未确认 Setup、非 Ready IPW 和缺检查点拒绝；
- [x] 中立程序到连续分包后操作/移动序列守恒；
- 第 N 个文件写入失败时旧发布包保持不变；
- UTF-8 路径、文件名冲突、清单校验和和确定性；
- 参考后处理不支持的多 Setup/多刀输入稳定失败。

## 6. G4—G6 后续重点

- 定义 `PostProcessorCapabilities`：单位、坐标、WCS、直线、圆弧平面、螺旋、固定循环、换刀、冷却、主轴、刀补和子程序；
- post 注册使用稳定 ID + version，Job 保存引用而非 UI 名称；
- 生产后处理必须提供黄金文件、解析/控制器验证结果和版本迁移策略；
- G41/G42 只能用于未在几何中重复补偿的路径，并验证进退刀段；
- 任何路径平滑/圆弧拟合必须在弦差、过切和 IPW 等价门禁内重新验证。

## 7. 构建与验收

```powershell
cmake --build build --config Release --parallel 16 -- /verbosity:minimal

ctest --test-dir build -C Release --output-on-failure --parallel 4 `
  -R "^(toolpath_program|machining_job|machining_project_controller|app_workflow_controllers|desktop_workspace|module_boundaries)$"
```

生产 post 变更除全量 Release 测试外，还必须运行其黄金文件与独立控制器/解析器检查；参考 NC Warning 不能作为生产批准。
