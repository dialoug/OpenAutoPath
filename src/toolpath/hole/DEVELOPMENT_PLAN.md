## 1. 目标与边界

模块最终应把已识别或人工确认的轴向孔稳定转换为可保存、可重建、可验证、可仿真和可后处理的工序。第一版范围是固定刀轴 SmallDrill、MediumHelical 和 LargeLayeredSpiral；可变刀轴、镗削循环、螺纹加工、在线测量和机床专有深孔技术不在当前范围。

完整闭环为：

```text
识别孔段/人工确认
  -> 物理孔分组与入口/Setup 解析
  -> 自动或人工刀具/阶段计划
  -> 固定轴孔刀路与孔间连接
  -> 结构、碰撞、覆盖和 IPW 验证
  -> Job 工序、统一程序和不可变 IPW 检查点
  -> 保存/重开/重建/后处理
```

当前缺口不在“是否能生成孔刀路”，而在生产级证明仍不完整：部分装配尺寸和采样预算仍可能只产生 Warning；参考 NC 不是控制器认证后处理；缺少覆盖更多钻型、深径比和真实夹具组合的固定验收集。

独立孔 IPW 仍使用 `HoleStockSimulator` 的 B-Rep 减料与精确毛坯比较。无法采用解析孔体的
螺旋扫掠按多个独立工具实体分批相减，处理相互重叠的线段扫掠；保留未被刀具覆盖的孔芯。
全部批次、最终拓扑和体积检查通过后才提交该工序，中途取消或失败保留父毛坯。
布尔运算使用空构造，先设置输入、容差、线程准入和取消监视，再执行一次 `Build()`。
完整成功的仿真进入比较阶段时复用初始/最终毛坯的校验结论，目标模型仍独立校验；
不跨工序跳过新材料状态的校验，也不对失败或未完成的仿真启用这一复用。

## 3. 不可破坏的契约

1. `mappingState != Ready` 的孔不得静默生成移动；未解析原因必须进入结构化诊断。
2. 人工确认的入口、Setup 和策略不得被自动重建覆盖。
3. 合并物理孔必须保留全部 `coveredSourceHoleIndices`，不能只保留代表段。
4. 钻削名义底面、实际指令底点、钻尖长度和突破深度必须分别表达。
5. 刃长需求与总可达长度是两个独立门禁，不能用刀具直径或默认值伪造。
6. 孔间 Rapid、Plunge 和 Retract 与切削移动一样进入碰撞验证；无法证明安全时抬到安全高度或拒绝。
7. 正式 Job 保存稳定输入和人工计划，不保存派生移动、OCCT 去料体或显示状态。
8. 原生 Multi-Dexel 更新只消费已验证移动；失败或取消不发布部分检查点。
9. `localBatch`、孔阶段、Setup、刀具和操作 ID 在保存/重建后保持稳定。
10. 参考 NC 只用于验证链和样例输出，未经机床/控制器确认不得标记为可投产。

## 5. H3 实施清单

### 5.1 统一验证证据

- 为每道孔工序发布版本化证据，至少覆盖输入指纹、完整刀具装配、所有移动类型、孔壁/底部/入口范围和加工后 IPW；
- 把未知切刃、总长、刀杆、刀柄或主轴包络从“兼容警告”分离：临时预览可显示诊断，正式 Job/导出必须失败；
- 对线性段、圆弧/螺旋和固定循环展开流执行连续扫掠，不只检查离散端点；
- 用统一孔覆盖模型区分钻削中心孔、螺旋孔铣和分层孔铣，不以一种半径规则覆盖所有策略；
- 通孔突破要同时验证目标材料去除和出口侧保护材料/夹具间隙；
- 证据指纹覆盖人工计划、刀具装配、Setup、碰撞场景、前序 IPW `stateKey` 和验证模型版本。

### 5.2 Job 与发布门禁

- `HoleMachiningJobService::regenerate()` 只有在验证证据和执行指纹一致时安装正式结果；
- `MachiningJobApplicationService` 将装配不全、Setup 未确认、碰撞场景变化映射为 `NeedsReview`/`Stale`，而非保持 Generated；
- 正式程序、IPW 节点和 Job 状态采用一次事务提交；预览失败保留最后有效批次；
- 自动计划与人工局部批次共享同一全局 `sequence`，但人工批次不得被全量再生成吸收。

### 5.3 必须新增的测试

- 球面钻尖、平底钻、U 钻和孔铣刀的刀具体/覆盖模型；
- 盲孔底部、通孔突破、交叉孔、叠孔段和靠近外壁孔；
- 刀杆/刀柄/主轴在孔口或夹具处碰撞；
- 螺旋相邻弦段之间碰撞而端点安全的反例；
- 未知装配、超采样预算、取消和错误前序 IPW 的发布拒绝；
- 保存—加载—人工计划重建后的阶段、来源段、指纹和程序确定性；
- 大孔阵列访问顺序优化前后安全结论不变。

## 6. H4/H5 后续重点

- 把控制器循环能力建模为后处理配置，不让生成器直接写某种 G-code；
- 固定循环必须有等价展开流，供预览、碰撞和 IPW 使用；
- 铰、镗、沉孔、中心钻等新增阶段使用新的稳定阶段/工具能力，不复用含义不符的枚举；
- 统计路线长度、精确碰撞次数、IPW tile 更新量、峰值内存和取消延迟；
- 建立小型确定性夹具供 CI 使用，大型 STEP/夹具组合进入单独真实件验收套件。

```powershell
cmake --build build --config Release --parallel 16 -- /verbosity:minimal

ctest --test-dir build -C Release --output-on-failure --parallel 4 `
  -R "^(hole_.*|machining_job|multi_dexel_ipw|toolpath_program|app_workflow_controllers|machining_project_controller|module_boundaries)$"
```

里程碑合并前还需运行 Release 全量测试。针对孔策略、安全或仿真的修改至少新增一个失败用例，并执行 `git diff --check`。

## 8. 维护规则与当前下一步

当前优先完成一个“严格发布模式”最小切片：定义孔验证证据结构，补齐完整装配连续扫掠，把证据接入 Job/IPW/程序三方原子门禁，并以盲孔、通孔、螺旋孔铣各一组回归固定行为。完成后更新本文件阶段状态与验证模型 ID。

新增工艺细节写在本文件相应阶段；跨 Job、IPW 或后处理的决策同步更新其模块规划。实现、公开头注释、测试和文档必须同提交。
