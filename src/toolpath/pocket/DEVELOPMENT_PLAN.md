## 1. 目标与完成定义

模块负责把识别或人工指定的平底槽/腔转换为固定刀轴、逐层、可验证的清料程序。它必须正确处理岛屿、逐层截面、开放出口、受保护材料、多刀余料和不同进刀方式，并把同一语义移动交给程序、仿真和 IPW。

```text
稳定面组/根内环
  -> PocketRegion 与真实逐层截面
  -> 刀心可达域、图案、进刀和层间连接
  -> 结构/边界/保护材料/装配验证
  -> 多刀余料链与统一 IPW
  -> Job 重建、中立程序、仿真与后处理
```

联动多轴、任意非平底三维腔、依靠显示网格判断材料、未经验证的开放轮廓猜测均不在当前范围。

## 3. 不可破坏的契约

1. `PocketRegion` 必须来自真实拓扑及确定性归一化，显示网格不得作为边界真值。
2. 外环、岛屿、开放出口和逐层保护材料必须在同一个局部 frame 中表达。
3. 开放截面只在来源明确允许时建立虚拟封口，普通区域遇到开放线框必须失败。
4. 图案只生成候选；最终 Cut/Entry/Link 必须再次通过公共安全装配器和验证器。
5. `moves` 是权威展开执行流；圆弧/螺旋等语义原语必须携带等价 fallback，二者端点和上下文一致。
6. 多刀余料工序只加工前序大刀不可达材料；`restMachiningPreviousToolDiameter` 和顺序进入指纹。
7. 受保护材料裁剪、岛屿和真实逐层截面不能因优化或图案回退而丢失。
8. 取消或任一层失败不得返回可发布的部分移动。
9. Job 只保存稳定来源和重建参数，不保存 `PocketRegion`、loops、moves 或 Dexel。
10. Multi-Dexel 是材料真值；B-Rep 仅用于显式方向过渡、兼容内核或按需审计。

## 5. P4 实施清单

### 5.1 严格安全发布模式

- 对 Cut、Plunge、Ramp、Rapid、Retract 的完整刀具/刀杆/刀柄/主轴包络执行连续检查；
- 把“达到采样上限”从可发布 Warning 改为严格模式失败；预览模式可保留诊断但不能进入正式 Job/NC；
- 将真实逐层保护材料、岛和上方累计包络加入低位连接证明，不能只验证当前底面二维域；
- 圆弧/螺旋按解析扫掠或有界弦差展开检查，语义原语与 fallback 结果必须一致；
- 验证证据指纹覆盖每层截面、保护形状、刀具装配、图案版本、前序 IPW 和全部工艺参数。

### 5.2 FreePath 验收

- 固定中央螺旋、径向波前、过载分段、岛屿绕行、Stay-down 连接和残料分量的确定性；
- 以材料参与角和实际去料量验证 `maximumEngagementAngleDeg`，不能只依赖几何估计；
- 对窄槽、尖角、薄桥、多岛、开口腔和保护凸台建立反例；
- 比较 Offset/ZigZag/FreePath 的路径长度、空移、峰值参与角、残料、过切、内存和取消延迟；
- 更新算法必须同步 `ADAPTIVE_FREEPATH_DESIGN.md`，行为模型变化时升级稳定算法 ID。

### 5.3 P4 必须新增的测试

- 刀心安全但刀杆/刀柄碰撞的深腔；
- 上层台阶材料导致低位连接不安全的层变截面；
- 显式保护凸台与岛组合、切片后才出现/消失的岛；
- FreePath 过载、细颈分裂、多连通剩余材料和取消；
- 圆弧端点安全但弧中碰撞、fallback 与原语不一致；
- 多刀余料无材料、错误前序刀径和错误 IPW 父键；
- Job 保存后默认参数变化仍重建原工序。

## 6. P5/P6 后续重点

- 将当前 Job 级 `pocketParameters` 收敛为明确的工序快照或版本化共享参数引用；
- CAM 工序树支持编辑图案、进刀、刀具、边界来源和多刀链，并预览下游失效范围；
- 多岛 Spiral 不允许静默变成语义不同的图案，回退必须由调用方确认或记录稳定诊断；
- 跨 Setup 材料过渡逐步减少 B-Rep 回退，但只能在 oriented Multi-Dexel 与精确审计闭合后切换；
- 性能优化继续受全局并行预算约束，不允许策略内部创建无界线程池。
- 2026-11-08：自动选刀适配器先租用调用方/全局额度，再供局部区域、候选和层调度
  细分；无额度时由调用线程串行执行。截面内部 OCCT 并行必须申请到正数且完整的
  额外额度，避免上限为 1 时误开并行。当前预算契约见
  [Core 开发规划](../core/DEVELOPMENT_PLAN.md)。
- 后续 P2/P3 已将适配器队列/内存策略提取为 private `PocketPlanningScheduler`，
  安全采样、保护材料准备、批次与通用验证统一继承预算；所有可变 OCCT 内部并行
  通过公共门禁和默认池需求校核。生成 STEP 对照方法见
  [基准记录](../core/PARALLEL_BENCHMARK_RESULTS.md)。

## 7. 构建与验收

```powershell
cmake --build build --config Release --parallel 16 -- /verbosity:minimal

ctest --test-dir build -C Release --output-on-failure --parallel 4 `
  -R "^(pocket_.*|dexel_.*|multi_dexel_ipw|machining_job|stock_simulation_workspace|toolpath_program|module_boundaries)$"
```

里程碑前执行全量 Release 测试。大型 STEP 和性能模型进入单独验收集；CI 快速测试必须使用仓库内小型确定性几何。
