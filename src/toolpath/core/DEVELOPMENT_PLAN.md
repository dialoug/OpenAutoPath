## 不可破坏的契约

1. Core 值类型不依赖 Qt Widget、Job、具体生成器或展示对象。
2. `moves` 是权威可执行展开流；非线性 primitive 必须带等价 fallback 与相同上下文。
3. 参数归一化不能把非法或未知值静默改成可发布输入。
4. 刀具上下文区分刀库默认、工序冻结快照和无效/缺失装配。
5. 取消、进度和并行预算通过执行上下文传递；显式调用方预算优先，未提供完整预算回调时由 `ensureToolpathParallelBudget` 接入进程共享池。
6. 公共验证报告使用稳定机器码；UI 文本不能成为领域判断条件。
7. Stock 比较和显示网格是调用方选择的派生行为，不改变输入材料。
8. 新公开头必须进入公开 API manifest，新跨目标 include 必须进入直接依赖图。

## 并行预算

孔批次及 Profile 候选、区域、深度层按任务数与可见逻辑 CPU 数分配并行度，
不再固定为 4。进程共享池只出租额外工作槽，调用线程也承担一个工作任务；
嵌套 Profile 任务可以继续租用剩余槽，作用域退出时归还，取消与异常不泄漏预算。
`OAP_CAM_MAX_THREADS` 可在进程启动前设置正整数上限；默认采用硬件并发度，
无效值回退硬件值，超出硬件的值会被截断。Tile 更新也遵守此预算；它不限制 UI 渲染线程。

2026-11-08：槽腔自动规划也接入上述预算。每个作业先通过 RAII 租约取得额外
工作槽，局部区域/候选/层调度只细分已获授额度；动态内存反馈不能突破该上限。
调用线程承担一个区域执行者，零额外额度时在调用线程完成计算；未提供控制对象
时使用全局池，完整的显式调用方预算（包括零额度）优先。线程启动部分失败时，
先等待已启动线程退出再归还租约。根工作流线程和内存采样线程不计入额外计算槽，
因此额度仍不是进程实际线程数上限。P2 将区域调度提取为适配器内私有实现；所有区域
及嵌套任务 join 后归还父租约，最终验证可重新借额度。直接同步调用仍不保证作业公平分配。

后续准入收敛：`HeavyJobScheduler` 以一个常驻执行线程、最多 32 个待执行项管理主要
后台重作业，FIFO 决定启动顺序；排队时不创建等待线程。显式 `cancelHeavyJob` 立即
移除尚未运行的任务并完成取消结果；直接修改 atomic 只保证启动前或运行中观察。
取消回调与失败映射在锁外执行，工作捕获先释放、future 后就绪。队列满、停止和递归
提交均返回明确拒绝原因；嵌套算法继续使用同步服务与非阻塞 worker 租约。
`HeavyJobWaitGuard` 和异步任务句柄保留异常退出后的等待，防止进度回调悬空。
该准入不覆盖直接同步 API、模型加载及 UI/渲染线程，也不强制覆盖调用方自定义预算。

同步 `ToolpathParallelScope` 只传递预算，不改变取消/进度契约；显式完整预算优先，
再继承当前同步 scope，最后借用全局池。纯 moves/primitives 验证与安全准备也遵守该预算。
已获额度的包装传播 scope 并等待所有任务结束后重抛异常；未持额度任务使用
`toolpathParallelForBudgeted`。异步根任务和原生 worker 必须显式建立 scope，不能保留
超出其生命周期的控制指针。

OCCT 内部并行统一使用 `ToolpathOcctParallelLease`：仅在已验证的原生后端默认池大小
不超过配置上限、完整正数额度获批且进程门禁可立即取得时放行。预算回调重入和构造
异常也受保护。Section、Cut/Common/Fuse、可变并行形状校验均通过该入口；未知/TBB
后端或预算不足时串行，不调整默认线程池。StockComparison 两个独立差集只在外层并行。

回归检查包括串并行刀路一致性、8 区域与 6 层自适应分配、孔批次调用方预算、
预算归还、取消原子性和真实 STEP 的凸台过切检查。

全局与槽腔局部预算的衔接和 OCCT 内部并行约束以上述契约为准；测量方法与性能对照见
[生成 STEP 基准记录](PARALLEL_BENCHMARK_RESULTS.md)。识别、预览和 MultiDexel Tile
仍有独立执行选项，不能将本预算解释为全进程线程硬上限。

## C3 实施重点

- 定义各特征可组合但不互相冒充的验证证据公共头部：输入/程序/父 IPW 指纹、模型版本、完成检查和发布级别；
- 明确 Preview 与 Formal 两种发布级别，未知装配或预算耗尽在 Formal 下必须失败；
- 为中立程序和执行流提供稳定内容摘要，避免各应用层重复实现不同哈希投影；
- 把控制器/后处理能力与几何参数分离，Core 只保存中立能力需求；
- 评审历史 `PocketToolpathOperation` 仿真载体，设计不丢失领域身份的通用执行 DTO；
- 保持旧公开 API 的迁移期，删除前必须有调用点和边界测试证明。
