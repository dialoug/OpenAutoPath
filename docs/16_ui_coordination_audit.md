# UI 与模块协调复查（2026-11-09）

本次按 STEP 导入、特征识别、装夹与参数、刀具来源、工序生成、预览播放、IPW、导出、保存与恢复检查主要 CAM 链路。检查对象是当前工作区，包含尚未提交的雕刻和单刀改造。

## 已修复问题

| 环节 | 原问题 | 修复后行为 |
| --- | --- | --- |
| 工序入口 | 统一面板和旧孔树各有一个全局“生成孔刀路” | 保留统一入口；树属性里的重建明确作用于整个同类工序组 |
| 操作状态 | 树内重建按钮与主入口可用性不一致 | 四类工序使用同一可用状态，繁忙或无模型时不能触发 |
| 工序树生命周期 | 退出时子树销毁信号可能回调已析构的成员，原生调试复现堆损坏 | 面板析构前断开子树回调，加入带选中项的重复创建/销毁回归 |
| 参数失效 | 孔仅记录一个标志，旧运行刀路仍可能进入播放和导出 | 四类工序均清理受影响运行结果，并独立保留待重生成状态 |
| 保存与恢复 | 修改参数但没有成功生成时，保存的仍是旧工序；重开可能静默回到旧参数 | 待重生成时明确阻止保存；成功生成才更新工序快照；重开恢复各类项目参数 |
| 刀具来源 | 活动刀库变更只影响孔，独立单刀却可能被误伤，雕刻专用库变化可能漏检 | 按实际刀库依赖失效；直接单刀不依赖刀库；雕刻专用库独立比较 |
| 预览切换 | 混合作业中非当前类别的正式工序不能切回预览 | 属性提供“显示此类刀路”；先检查对应关系和结果有效性，再切换，不隐式生成 |
| 混合项目身份 | 孔与槽腔/轮廓提交使用不同公共识别版本，后生成的类别使已有孔结果指纹失效 | 仅首次缺失时初始化公共版本，后续提交保留既有身份，执行指纹校验不放宽 |
| 定位语义 | 未载入当前播放的工序仍有定位/单独显示入口 | 明确显示“未载入预览”，不跳错位置；可显式切换到对应刀路 |
| 播放显隐 | 静态刀路隐藏后，播放的剩余刀路仍可能出现 | 剩余路径与工序隐藏/独显同步，保留原始移动索引 |
| 仿真入口 | 项目 IPW 时间线显示“继续 OpenGL”，实际没有对应混合程序动画 | 项目时间线只提供已实现的 IPW 查看/关闭操作，原槽腔和轮廓动画入口保留 |
| 繁忙与取消 | 部分交互仅切换光标，没有统一更新主窗口状态 | 进度与显式繁忙状态支持嵌套，统一禁用命令并接入关闭取消 |
| 装夹参数 | 旧单装夹原点字段仍可编辑，但现有规划/导出不读取它们 | 移除无效输入，显示实际使用的六面工作坐标与确认信息 |
| 保存/导出入口 | 没有可用程序时可能隐式尝试生成孔刀路 | 明确要求先生成或显示所需工序，不擅自切换加工类别 |

## 状态约定

- 参数、装夹几何或依赖刀库变化：只将受影响类别标记为待重生成，保留正式定义。
- 失败或取消：不恢复旧结果为当前配置，不清除待重生成标记。
- 成功生成另一类别：不会清除尚未解决的其他类别标记。
- 当前类别有效、其他类别待重生成：当前类别可以单独导出；完整项目保存与 UI 项目仿真入口要求先解决待重生成项。
- 禁用工序仍保留配置变更信息，重新启用不能绕过重生成。
- 仅核对装夹确认状态不改变刀路几何；改变原点或轴向则使相关结果失效。
- 预览、定位和显隐不改变正式工序顺序、刀具快照或加工参数。

## 仍有边界

1. 原生窗口截图尝试连续超时，本次未完成真实桌面的逐页视觉验收。Qt 控件/回调测试不能替代不同 DPI、分辨率下的排版检查。
2. `MainWindow::openMachiningJob()` 仍同步调用项目读取与刀路重建，大型 `.oapjob` 的恢复可能长时间阻塞界面。应另行接入后台调度和完整取消传播，不能仅增加一个假进度条。
3. 导出仍明确以当前预览工序类别为范围；项目 IPW 则按全局启用工序顺序执行。两者范围不同，输出区已明确当前预览类别。

因此，本次补齐了已确认的跨模块状态与交互断点，但不能据此宣称所有模型、所有窗口尺寸和所有用户操作序列均已验证。
